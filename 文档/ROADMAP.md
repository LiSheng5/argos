## 2. 仍未做（**有意为之，不是欠账**）

| 项 | 判断依据 | 触发条件 |
|---|---|---|
| **真机 backend** | 本项目**没有真实硬件**，且**不写假的真机代码冒充**（`--backend go2` 如实报"尚未实现"退出码 2，别去"修"它）| 拿到硬件 |
| **Evaluator 独立成模块** | 当前"判分"就等于 `ActionResult`，抽成接口在本世界**无可观测差异**（路线终点就是目标，不存在"跑完没到"）→ 只有抽象、没有可验证收益 | 世界变复杂：多目标 / 带前置条件的任务 |
| **变点检测替代固定周期复核** | 文献的"主动遗忘"作用于**仍在使用的臂**；而我们复核的是**已被避开、不再去走的路线** → 没有新观测，检测器**根本不会触发**。它替代不了主动试探 | 做成"当前路线的行为变了"这个信号，与 `revalidate_every` **并存** |

## 3. ⚠️ 覆盖缺口（2026-09-19 新查出 —— **这两条比技术债更该先补**）

> 共同性质：**功能做完了，但 benchmark 没覆盖** → 结论的适用范围被高估。

1. **失败注入器做了 9 类，benchmark 只测了 1 类**（实测：全矩阵里只用到 `obstacle_blocked`）。
   → 现在"反思/记忆有效"的结论**只覆盖「被障碍挡住」这一类失败**。
   超时 / 定位丢失 / 执行器故障 / 链路延迟 / 缺传感器 / 路径失效**都没进过实验**。
2. **感知层（噪声 / 量化 / 失灵 / 探测半径）没进 benchmark**（实测：`argos/benchmark/` 里
   没有任何 `sensors` 引用）→ 只在单测里验证过"失灵会 fail-closed"，
   **"传感器不可靠时 agent 表现如何"从未被量化**。

→ 建议下一步优先补这两条：加一个「失败类型 × 感知状态」的实验维度
（纯场景配置工作，不需要改认知层）。

## 4. 已知的技术债（有明确触发条件就动手）

- **Planner 仍绑 `MiniWorld` 的路线拓扑**（`argos/run.py::_route_topology` 取不到时如实抛错，
  不假装 backend 无关）→ 真机 backend 要么自带拓扑，要么把拓扑改成从 `Observation` 里取；
- **反证削弱规则粗糙**（成功一次降一级），更严谨的形态是把路线选择当**非平稳多臂老虎机**
  （折扣/滑窗或变点检测），而不是二值 `avoid`；
- **教训只在进程内存**，尚无持久化与人工审阅入口；
- **阈值已扫过参但未做交互扫描**（单变量，见 `文档/SWEEP.md` §3）。
