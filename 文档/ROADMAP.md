## 3. ✅ 覆盖缺口 —— **已补上**（2026-09-19）

原来查出的两条缺口（功能做了、benchmark 没覆盖）已补齐，benchmark 从 24 场景 → **35 场景 /

| 缺口 | 补法 | 结果 |
|---|---|---|

补齐过程中**抓到并修掉一个真缺陷**（详见 `文档/REFLECTION_LOOP.md` §1b）：
`route_ok` 原来用 `failures == 0` 当判据 → 非路线类失败也被算成"这条路不顺" →
语义层把路线降权 → **agent 因为定位漂移改走远路**（证据：学习臂比无记忆臂多 2.00 个动作、
失败数却一样）。现在判据与 Procedural 层同源（只用 `ROUTE_REASONS`）。

### 补完之后**新暴露**的一个问题（待你拍）

**传感器一次抖动 = 整轮报废**：定位失灵 → 闸门 fail-closed 拒动 → 而 `SAFETY_REJECTED`
不可学习、**不重试** → 本轮直接结束。实测 `sensor_pose_dropout` 场景六组配置**全部 0% 成功率**。

- 现状是"安全优先"（宁可不动、也不凭猜的坐标走）—— 方向没错；
- 但"站着不动等 0.2 秒再看一眼"也是安全的，而且能救回整轮任务。
- **这是一个取舍，需要你定**：要不要在"缺数据被拒"时允许 **WAIT 后有限次重试**？
  影响面：`brain.py` 的失败分支 + 两条测试。

### (1) 缺数据被拒 → 整轮报废 ⏸ 等定
- **现象（实测）**：`sensor_pose_dropout` 场景（15% 整轮失灵）**六组配置全部 0% 成功率**。
  链路：定位失灵 → 闸门 fail-closed 拒动 → `SAFETY_REJECTED` **不可学习、不重试** → 本轮结束。
- **候选方案**
  | 方案 | 做法 | 代价 |
  |---|---|---|
  | **a) WAIT 后有限重试**（我的倾向）| 被"缺数据"拒后原地 WAIT 0.2~0.5s 再看一眼，最多 N 次 | 要定 N；trace 里要如实标"这是重试" |
  | b) 保持现状 | 把"缺数据"当环境不可用，如实失败 | 任务白跑；但语义最干净 |
  | c) backend 层去抖 | 连续 2 次读不到才判失灵 | 上层无感；但掩盖了"真失灵" |
- **影响面**：`brain.py` 的失败分支（~5 行）+ 两条测试；不动闸门、不动安全语义（等待期间不移动）。
- **关键判断点**：**"站着不动等一会儿"是安全的**，所以它不违反 fail-closed 的初衷。

### (2) 反证削弱规则粗糙 ⏸ 等定
- **现象**：探针成功一次就把教训 `hits` 降一级 —— "偶然成功一次"和"真的恢复了"没区分开。
- **候选**：a) 要求**连续 2 次**成功才降级；b) 把路线选择当**非平稳多臂老虎机**（折扣/滑窗 UCB）；
  c) 保持现状，只在文档里如实标注局限。
- **影响面**：`reflection.py::record_success` + 相关测试。

### (3) 教训只在进程内存 ⏸ 等定
- **现象**：`AgentMemory` 纯内存，跑完就没了；也没有人工审阅/删改教训的入口。
- **候选**：a) JSON 落盘 + 启动加载；b) 加 `python -m argos.lessons` 之类的 CLI 供人工审阅
  （文献里叫 "operator curates the buffer"）；c) 保持内存（benchmark 场景下够用）。
- **影响面**：新文件为主，几乎不动现有逻辑。
