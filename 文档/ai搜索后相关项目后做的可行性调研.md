# 机器人可行性调研（复用 NPC V4架构）

## 1. 宇树机器人大脑原理

三层模型（王兴兴 2026-08-20 在世界机器人大会首次公开技术路线）：

| 层 | 职责 | 技术 | 开源/接入状态 |
|---|---|---|---|
| 硬件骨架 | 自研伺服电机、Jetson 计算平台、4D 激光雷达、IMU | Go2 / B2 / G1 / Z1 | 采购真机 |
| **小脑**（软件） | 高频实时运动控制（kHz） | MPC + WBC + BeamDojo 强化学习 | **完全开源**：`unitree_rl_gym`、`unitree_guide`、SDK |
| 软硬件协同 | 毫秒级控制闭环 | CAN/实时总 + ROS2 中间件 | **完全开源**：`unitree_ros2`、`unitree_mujoco` |
| **大脑**（AI+） | 意图理解 → 决策 → 执行 | **VLA** 视觉-语言-动作 + **WMA** 世界模型（预测未来帧后预演动作），双线并行 + 物理 AI 自进化 | 部分开源：`UnifoLM-VLA-0`、`UnifoLM-WMA-0`；**仍在研发期** |

关键：宇树把"会走、稳"（小脑）开源了，把"会思考、听话做事"（大脑）留给业界填。**这正是你复用的位置。**

## 2. NPC 大脑 → 机器人大脑 复用映射

| NP C 大脑模块 | 机器人复用方式 | 是否需要新增 |
|---|---|---|
| 三角色 B1 对话 / B2 编译 / A 审查 | 平移。B1 生成回复，B2 把意图编译成任务单，A 做合规审查 | 否（直接搬） |
| 落账口 `book()` | 平移：所有"承诺去执行"必须落账才真正执行，防"嘴上答应不做事" | 否（直接搬） |
| 记忆三阶段（反思/关联/遗忘） | 平移：任务与经历回流到长期记忆 | 否（直接搬） |
| 动作白名单 `ALLOWED_TASK_ACTIONS` | **替换**：`gather/move/craft` → `walk_to/巡检/抓取/放下/返回` 等**运动原语** | 是（改列表） |
| 语音 TTS（edge-tts） | 平移 + 补 ASR（语音输入识别，可用 faster-whisper） | TTS 否；ASR 新增 |
| 执行出口 `server.py` | **新增执行适配器**：落账任务 → `unitree_sdk2` / `ROS2` 下发 | 是（核心新增） |
| 安全（A 审查白名单 + 服务器绑定 127.0.0.1） | **升级**为真机安全：限速、急停、力矩上限、人体距离、电量门控 | 是（加强） |

## 3. 业界已有人做，架构已被验证 —— 但没人做"完整脑层"

| 项目 | 机型 | 做法 | 与你的差异 |
|---|---|---|---|
| **Claudia**（开源） | Go2 | 本地 LLM（Qwen2.5-7B）+ `SafetyCompiler`（不可绕过的安全门）+ `action_registry` 动作白名单 + 三级电量门控 | 它验证了"白名单 + 不可绕过安全门 = A 审查/落账"的正确性；但没有 B1/B2/A 三角色分工，也没有记忆三阶段 |
| **Willy**（G1 EDU+，OpenClaw 双层脑） | G1 | 快路径（简单问答，Qwen2.5-7B 路由）+ 复杂路径（大模型 + 工具调用）+ HTTP action dispatcher + DDS | 快慢路径 ≈ B1/B2 分工思想，但无"落账口"账本，承诺与执行未强绑定 |
| **MotionCorps**（hackathon） | G1 | 微调 Ministral-8B + LLaVA 视觉 + 关节角 60Hz | 直达关节层，无高层任务账本 |

**结论**：单点能力别人都有，但**"三角色决策 + 落账口防承诺不执行 + 记忆三阶段"这套把'说/想/做'强度绑定的完整脑层，尚未见同类实现 —— 这是你的差异化卖点。**

## 4. 机型与接入门槛 / 成本选型

| 机型 | 形态 | 二次开发门槛 | 参考价 | 接入方式 |
|---|---|---|---|---|
| **Go2 EDU** | 四足 | 完整开发接口，ROS2 + Python/C++ SDK，可配 Orin NX | ¥39999 起 | `unitree_sdk2` / `unitree_ros2`，最适合做 **MVP/试用** |
| Go2 PRO | 四足 | 支持 SDK，无完整科研口(足端力传/Orin 可选) | ¥18600 起 | 可用但受限 |
| Go2 AIR | 四足 | 不支持二次开发 | ¥9997 起 | 不可接（排除） |
| **B2 / B2-W** | 工业四足 | 工业级，IP67、重载 | 贵（企业） | `unitree_sdk2` / `unitree_ros2`，适合**企业巡检场景** |
| **G1 EDU+** | 人形 29 自由度 | 开发者友好：Python SDK + DDS topics + 内置相机/手/Jetson | 高（走科研/企业） | 已成开源社区共识，适合**作人形演示/接待** |
| D1 / Z1 | 机械臂 | JSON over DDS，10Hz 控制（mode2 平滑轨迹），单/双臂 | 低到中 | 适合**桌面操作任务（抓取/整理）** |
| H1 | 成人形 | `unitree_legged_sdk`/`unitree_sdk2` | 高 | 实验室级 |

**参考路线建议**：MVP 用 **Go2 EDU**（四足、门槛低、价适中、社区多）；想演示"抓取/整理"再加 **D1/Z1 机械臂**；企业对外的卖点现场放 **B2**（工业）+ 人形 **G1** 做接待。**每个机型都要先过 `unitree_mujoco` sim2real，再上真机。**

## 5. 技术风险与对策

| 风险 | 对策 |
|---|---|
| 真机安全（LLM 幻觉导致危险动作） | A 审查升级为真机安全闸门：运动原语白名单 + 限速 + 急停 + 力矩上限 + 电量门控（参照 Claudia 三级电量门）；**LLM 零关节/零文件直控能力** |
| 算力不足（真机 Jetson 跑大 LLM） | 大脑层与运动层分离：真机只跑小脑 + 适配器；脑层可跑在云端/本地推理机（如 Claudia 用 Qwen2.5-7B 本地、Willy 用远端 A40 + 真机 Orchestrator） |
| 延迟（对话要像人一样快） | 快慢路径分级：简单指令快路径（短时延），复杂任务慢路径（15~25s 可接受） |
| 落账口在真机上的强度 | 复用原"LLM 零文件能力"设计：机器人路径只允许 `argos.*` 白名单智能化动作，LLM 不直接碰 SDK 文件系统 |
| 授权/合规 | 以"开源 + 设备端可离线"为默认（Claudia/Willy 都完全 on-premise，无数据出网），降低企业顾虑 |
| 成本 | MVP 一个 Go2 EDU 即可起步；先用 `unitree_mujoco` 仿真验证，再买真机 |

## 6. sim2real 验证路径（先仿真后真机）

1. `unitree_mujoco` 装仿真（Go2 或 G1），复用 `unitree_sdk2_python` 的控制代码无缝进仿真。
2. 搭建最小闭环：文本指令 → B2 编译 → A 审查 → 落账 → 执行适配器 → 仿真运动原语 → 状态回读写记忆。
3. 仿真通过后再上真机（对照 Claudia：先文本、后语音、再无线语音）。
