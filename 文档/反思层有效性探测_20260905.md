## 2. 四个缺陷的严重度与触发条件

### D. 闭环未接上（严重度：高，但属于未完成功能而非 bug） — ⬜ **未修**（新功能，需单独设计）

`argos/` 里 `recall()` 只在 `brain.py:505` 定义，**没有任何生产调用点**。
反思产物的唯一读取方是给人看的：`/api/memory`（全量）和 `/api/state`（最近 5 条）。

含义：反思不改变编译、不改变选日常、不改变安全闸。**反思层当前价值 = 可观测性（人能看狗在想什么），不是智能。**

> 建议的接线点（未实现）：
> - `instruction` 类记忆 → 影响 `DEFAULT_ROUTINE` 权重或地点表
> - `recall()` 结果 → 注入 `try_command` 的 LLM 上下文（让狗"记得"上次在门口摔过）
> - 失败冷却的提示语 → 从反思里取失败原因，而不是只报 `刚失败过`

### B. 编造无校验（严重度：中高，接上闭环后升级为安全相关） — ✅ **已修**（三层护栏，见 §4.1）

`_llm_reflect` 与 `_reflect_typed` 都只靠 prompt 里的"禁止编造"约束，
**没有任何代码级校验**：LLM 返回的文本直接 `append` 进记忆卡，`importance` 由 LLM 自报（typed 路径）。

现在它只污染展示（人在 `/api/memory` 看到假记忆）。
可一旦 `recall()` 接进决策回路，污染的记忆会驱动一条真狗——**这是机器人项目，不是聊天机器人。**

> 建议的校验（未实现）：反思文本与源事实做实体/关键词交集校验，
> 出现候选批之外的实体时丢弃该条并降级到规则摘要；typed 路径的 `importance`
> 也应夹取到源批重要性区间内，而不是放任 LLM 自报 9 分。

### E2. 噪音闸误吞高重要性记忆（严重度：中，真机上**容易**触发） — ✅ **已修**（重复模式不吞，见 §4.3）

触发条件：未反思批唯一内容 < 3 种，但重要性之和 ≥ 18。

真机场景很常见——狗反复撞同一堵墙：
`没做成: 去门口（电量不足）` 重复 5 次（各 4 分，和 20 ≥ 18）→ 唯一内容 1 种
→ 判定噪音 → 静默全部标记 `reflected`，**不产出任何结论，且这些记忆永久失去反思机会**。

悖论在于：最需要被反思总结的"反复失败模式"，恰好是内容高度重复的那一批，
而噪音闸按"内容多样性"判定，正好把它们判成噪音。

> 建议（未实现）：唯一内容 < 3 但**内容重复度高且总和 ≥ 阈值**时，
> 判定为"模式"而非"噪音"，走单条路径产出一条"反复失败"结论，而不是静默翻篇。

### E1. 候选窗口无老化（严重度：低—中） — ✅ **已修**（改按重要性取候选，见 §4.3）

`cands[:8]` 取的是卡上**最老**的 8 条未反思记忆。若这 8 条重要性之和 < 18，
`maybe_reflect()` 返回 None **且不翻篇** → 指针永远不动，后面的大事永远排在第 9 位之后。

`brain` 自身写入的最低分是 4（失败记忆），8 条 = 32 ≥ 18，所以**纯自动运行不会触发**；
但记忆卡是"可编辑 JSON"（README 明说改文件即改记忆），手改出低分条目就会哑火，
且**无法自愈**（只能人工删改那些条目）。

> 建议（未实现）：不够阈值时也推进指针（翻篇最老的 N 条），或按重要性排序取候选而非按时间。

## 3. 不是缺陷但值得知道

- **无 key 时"反思"是复述不是归纳。** 规则兜底生成 `我最近做了这些事：A；B`（直接拼接原文）。
  真正的归纳要配了 `ARGOS_API_KEY` 才有。文档里统称"反思归纳"，名与实有落差。
- **反思只有一层。** 反思条目被 `kind != "reflection"` 排除在候选外，不会二次抽象，
  没有 Generative Agents 那种"对反思的反思"层级。
- **记忆卡只增不减。** 归档只是打 `archived` 标记，条目永远留在 JSON 里（400 tick 已 93 条）。
  长跑下文件会持续膨胀，没有冷存或截断策略。
- **护栏只在假 LLM 下验证过（重要边界）。** 假 LLM 能证明"护栏逻辑对"，
  证明不了"真模型会触发它"：真模型会不会按格式给 `evidence`、给了能不能对上源事实、
  编造率多少 —— 这些没配 key 就无法实测，**不要当成已验证**。
  探针已备好：`tests/_probe_reflection.py` 的 **F 节**，配 `ARGOS_API_KEY` 后重跑即可
  （没 key 自动跳过，不联网不花钱）。关注四个数：typed 解析成功率 / evidence 提供率 /
  evidence 命中率 / 最终入库 vs 被拦。每条内容仍需**人工过一眼** ——
  护栏拦的是"引用对不上"和"实体凭空冒出"，**不等于"内容正确"**。

## 4. 修复记录（2026-09-05 晚）

改动集中在 `argos/brain.py`（+ `memory.py` 开两个口子），**未动执行器与安全闸**。
7 条新钉在 `tests/test_reflection_guards.py`，全量 **133 passed**。

### 4.1 编造三层护栏

| 层 | 做法 | 拦什么 |
|---|---|---|
| 层1 evidence 溯源 | typed prompt 要求每条引用源事实原文，代码校验 `evidence` 必须是 `facts` 的子串（≤60 字）；对不上 → 该条丢弃 | 假引用 / 改写引用 / 整篇复读 |
| 层2 世界实体 | 反思提到的世界实体（同义词族 + 地点表）必须源事实里也有 | "凭空冒出一个地点/对象" |
| 层3 重要性夹取 | 反思重要性上限 = `min(8, 源批最高分 + 1)`，LLM 自报的 9 分不算 | 编造内容拿高分长期霸占检索顶部 |

**fail-closed 语义**：typed 路径解析成功但**逐条校验全不过** → 不再试单条路径
（模型输出既然不可信，就不该再问一次），直接落到 100% 有根的规则摘要。

**不会误杀**：抽象归纳（"主人喜欢看我干活"）不含任何世界实体，空集 ⊆ 任意集，恒真放行。

### 4.2 单字地名的坑（修护栏时自己踩到的）

层2 最初对地点表做朴素子串匹配，结果编造用例里"邻居**家**的猫"被判为"提到了地点家" ——
拦是拦住了，**判据是错的**：照这个逻辑，"回家/大家/家里"都会被误杀。

已改为 **只认 ≥2 字地名**（单字地名中文没有词边界，宁可漏拦也不可误杀），
并补了反向钉 `test` 里的"主人今天带我回了家"用例。**教训：护栏的正确性要用反例验证，
不能只看它拦住了什么，还要看它放过了什么。**

### 4.3 候选窗口与噪音闸

- **E1**：`_reflect_candidates()` 改为按 `(-importance, created_at)` 排序取窗口，
  喂给 LLM 前再按时间排回。大事不再被低分碎事埋在窗口外，哑火且无法自愈的问题消失。
- **E2**：噪音批先查 `_repeated_pattern()` —— 同一件事出现 ≥2 次即判为**模式**，
  产出规则复述 `反复发生：X（2 次）`（mtype=episodic，**不调 LLM**，
  只报事实与次数，不推断原因）。真噪音（内容不同但不够多样）仍静默翻篇。

### 4.4 反向验证（家规：测试钉必须反向验证）

`.workbuddy/verify_guards.py` 把每道护栏逐一退回旧行为，跑对应钉子确认会炸，
再 `shutil.copy2` 还原（**不用 `git stash`** —— 本机 safe-delete 会拦删除动作）。

✅ 层3 重要性夹取   → test_reflect_importance_clamped_to_source 炸了

### 4.5 护栏覆盖不到的部分（重要，别误以为全拦住了）

`tests/_probe_reflection.py` 的 B5 用例实测：

- **拦不住**：单条路径 + 纯抽象编造（"去了公园""养了三只猫"这类**新词不在世界实体表内**、
  且模型**不按格式给 evidence**）。
- **原因**：纯规则做不了通用编造检测。抽象归纳必然产生新词，要区分
  "合理的概括"和"事实断言的编造"需要 NLI / 事实一致性模型，不是几行子串匹配能解决的。
- **影响**：这类编造现在不会驱动行为（`recall()` 零调用），只污染给人看的 `/api/memory`。
- **接线前必须补**：接闭环时，要么强制 typed 路径并要求 evidence（不给依据就降级规则摘要），
  要么引入事实一致性校验。**这两条没做之前，不要把 `recall()` 接进决策回路。**

**结论：与本次改动无关**，两版失败模式一致。根因是物理仿真 + DDS 闭环对

真要钉死确定性路径，应该用**极小预算强制触发**（小结里那招），而不是赌一次行走结果。

## 5.6 真 LLM 验证（2026-09-06，配 OpenCode Zen 免费模型实测）

上一版报告明确标了"护栏只在假 LLM 下验证过"——这次配了真 key，把那个边界补上。
**结论：免费模型撑不起 typed 结构化反思，层1（evidence 溯源）在实际部署里会一路降级到规则摘要。**

### 5.6.1 顺带修掉两个真 bug

| 问题 | 根因 | 修法 |
|---|---|---|
| `http 403`（LLM 静默降级） | `urllib` 默认 UA `Python-urllib/3.x` 被 Cloudflare 拦（`error code: 1010`） | `llm.py` 显式加 `User-Agent: ArgOS-llm/1.0` —— **任何走 CF 的 API 都中招，不只 Zen** |
| 读超时 | 默认 `timeout=20s` 对推理型模型生成 300 token 不够 | 记为已知限制，未改默认值（项目定位 20s 对 deepseek-chat 够） |

### 5.6.2 免费模型逐个实测（`/zen/v1/models` 直接问服务端，不信文档）

| 模型 | 结果 |
|---|---|
| deepseek-v4-flash-free | ❌ 400 `Model is unavailable` |
| muse-spark-1.2/1.3-free | ❌ 403 `RegionError`（中国大陆不可用） |
| ling-3.0-flash-fin-free | ⚠️ 能 200，但 endpoint 时好时坏，返回内容为空 |
| mimo-v2.5-free / nemotron-3-ultra-free / nemotron-3.5-lightning-free | ✅ 能返回文本 |

### 5.6.3 关键结论：nemotron-3-ultra-free 做 typed 反思，成功率约 1/3（不稳定）

拿 nemotron 真跑 `_reflect_typed`（max_tokens=500 后）实测 3 轮：

| 轮 | 输出 | 结果 |
|---|---|---|
| 1 | 自然语言 `Memory 1: ... Importance 9. Evidence: "..."` | ❌ parse 失败 |
| 2 | 自然语言 `importance 7, evidence "完成: 去门口"` | ❌ parse 失败 |
| 3 | 完整 JSON 数组（带 evidence） | ✅ 成功 |

三个根因，全是被"推理型 + 免费"拖累：
1. **推理型**：把英文思维链写进 `content`，`max_tokens=300` 时 JSON 被 CoT 截断（0/5）。
2. **格式漂移**：即便给了预算，也常输出自然语言（`Memory 1: ...`）而不是 JSON 数组。
3. **慢 + 不稳**：单次要 6–12s，`20s` 默认超时偏紧，偶发 500/`bad response shape`。

含义：**typed 结构化反思（层1 evidence 溯源）在 nemotron 上只有约 1/3 概率成功**，
其余 2/3 会 fail-closed 落到规则摘要（不崩、不编造，但反思质量打回"复述"档）。
这不是坏消息——fail-closed 本来就是这么设计的——但要如实说：

> nemotron 免费、能用，但**别指望它的 typed 反思稳定**。要么接受 1/3 成功率
> （省 token，反思时好时坏），要么给 `parse_typed_reflection` 加一层"自然语言兜底"
> （解析 `Memory N: content, importance X, evidence Y` 格式，能救回大部分但解析脆弱），
> 要么换一个守 JSON 的非推理模型（deepseek-chat / Zen 的 deepseek-v4-pro、glm-5）。

### 5.6.4 代码侧的落地（这轮真实验证顺带改的）

| 文件 | 改动 |
|---|---|
| `llm.py` | ① UA 显式设为 `ArgOS-llm/1.0`（Cloudflare 1010 根因，任何 CF 保护的 API 都受益）；② `timeout` 支持 `ARGOS_TIMEOUT` 环境变量（默认 20s 对慢模型不够） |
| `brain.py` | `REFLECT_TYPED_MAX_TOKENS = 500`（typed 反思输出预算，300 会被推理型 CoT 截断） |

### 5.6.5 对护栏设计的一句话修正

护栏逻辑本身没问题（假 LLM 下 5/5 钉子有效、反向验证通过）。但"层1 evidence 溯源"
这条**在真实免费模型下形同虚设**——模型要么出不了 JSON、要么格式漂移，层1 多数时候
落空。所以接闭环时，防编造的**主力是层2（世界实体）+ fail-closed 降级**，不是层1。
层1 只有在"配了守 JSON 的模型"时才真正生效。

## 5.7 反思闭环已接（2026-09-06）

上一版结论"recall() 零调用、反思只写不读"——已接上两条通路（`argos/brain.py`）：

| 通路 | 做法 | 铁律 |
|---|---|---|
| **话术层** | `try_command` 的 LLM 措辞附带 `_recall_context()` 召回的相关记忆，狗回复会"记得"过去的成败 | 只影响"怎么说"，编译/落账/安全闸永不读记忆 |
| **行为层** | `_instruction_hints()` 从 instruction 类反思记忆提取白名单动作词（巡逻/拿/放下），命中则对应自主日常权重 ×3（`_INSTRUCTION_BOOST`） | 只认白名单词；编造的"去公园"不触发任何动作；最坏情况多巡逻几次，仍过 SafetyGate |

8 条新钉在 `tests/test_reflection_loop.py`，反向验证 2/2 有效（`verify_loop.py`）。

**诚实的边界（别把闭环当成"反思驱动行为"）：**
1. 话术层只在**配了 LLM** 时生效；无 key 时规则话术一字不变（确定性兜底不被动）。
2. 行为层依赖 instruction 类记忆的产出，而免费模型（nemotron）typed 成功率仅 ~1/3、
   且 instruction 占比更低 —— 所以这条通路**当前很少触发**，是"接了、通着、但基本空转"。
3. 两条通路都是**启发式关键词**，不是语义理解。要真正的"反思 → 自主规划"，
   还是得等一个守 JSON 的模型把 instruction 稳定地提出来。
