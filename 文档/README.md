# 文档/ —— 索引与维护规则

> **这个目录装"已成立的事实"**：架构、接口、实测数据、运维口径。
> 未定的事 → `待办/`；与用户商议过的原文 → `商议/`（两者都不推送）。
> 想看什么，先在下面 §二 找；想写新文档，先看 §四。

---

## 一、四个区怎么分（别放错）

| 区 | 装什么 | 推送？ |
|---|---|---|
| **`文档/`**（这里） | 已成立的事实：架构、规范、实测数据、基线 | ✅ 推送 |
| **`文档/archive/`** | **历史快照**：已冻结 / 已完成的审计、流水账、立项调研 —— 只记录"当初为什么"，不描述现状 | ✅ 推送 |
| **`待办/`** | 未完成 / 待决策 / 待商议 / 等外部条件 | ❌ gitignore |
| **`商议/`** | 与用户商议的原文（汇报、路线讨论、探测报告、文献调研） | ❌ gitignore |

⚠️ **推送区引用不推送的文件时，必须写明"（本地，不入库）"** —— 否则仓库读者看到的是断链。

## 三、五条规矩（这个目录吃过亏才立起来的）

1. **单一信息源**：同一件事只在一处写正文，别处只放指针。
   反例（都发生过）：测试数字抄了四份全部过期；ROADMAP 自己 §1 与 §3 互相矛盾。
2. **生成物勿手改**：B 组三篇改了也会被下次重生成冲掉，要改就改生成它的代码。
3. **引用必须逐字核对**：写下"见某篇文档"之前，先确认那个文件真实存在、路径逐字对得上。
   2026-09-21 一次性查出 9 处断链（其中 2 处在**代码注释**里）——
   **审查时要连 `argos/**/*.py` 与 `tests/*.py` 一起扫**，只扫 markdown 会漏。
4. **历史快照进 `archive/`**：冻结 / 完成的材料搬进子目录，并加"⚠️ 已归档 + 日期 + 指向现状"的头部。
   这样它就不再被当作"现状文档"，读者不会拿它跟现状对照（2026-10-16 立）。
5. **提交前跑两道硬门**（退出码非 0 就别提交）：
   - `python scripts/check_docs.py` —— 查死链 / 数字漂移 / 索引完整性 / 过期词提示。
     带豁免规则（历史快照不假红），且**真漂移一定会被抓到**（已做负向验证：
     把 `35 场景` 改回 `24 场景` 会精确报红）。
   - `python scripts/check_generated.py` —— **生成物新鲜度门**：把 B 组三份
     （+ demo 的 JSON）各重跑一遍，与仓库里的逐行比对；漂了就报"第几行 + 重生成命令"。
     立它的原因：已**两次**出现"生成物与生成器对不上"（`report.py` / `demo.py` 写死"四组"）。
     全查约 5s；只查一份用 `--only demo`。

## 四、新文档该不该建 / 放哪

| 情况 | 做法 |
|---|---|
| 描述已实现的东西 | 放 A 组，并在本文件登记表里加一行 |
| 跑命令能产出的数据 | 放 B 组，并**在文件顶部写清生成命令** |
| 某个时间点的审计 / 汇报 / 已完成的设计 | 放 `archive/`，**顶部标"⚠️ 已归档" + 日期 + 指向现状** |
| 还没定、等用户拍 | **不建** —— 记 `待办/待办清单.md` 的条目里 |
| 与用户商议的原文 | **不建** —— 放 `商议/` |

建之前先问一句：**这条信息已有的哪篇装不下？** 装得下就补进去，别开新文件。
