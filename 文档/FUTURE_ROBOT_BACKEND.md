# FUTURE_ROBOT_BACKEND —— 未来接真机时的 backend 规范

> **本文是规范，不是实现。** 本项目当前**没有任何真实硬件**，
> `argos/backends/go2/` 里只有这份规范（`README.md`），**不写"看起来能跑"的真机代码**。
> 指令原话：不许伪造 real executor。这条红线在本文 §6 再强调一次。

---

## 1. 为什么现在就要写这份规范

新 runtime 的整套设计都是为了这一句：**换身体只换 backend，上层一行不改。**

所以规范的意义是"把接口契约写清楚"，让未来那次接入**不走样**：
- 哪些是**必须**实现的（协议方法）；
- 哪些是**必须复用**的（安全闸、缺数据语义）；
- 哪些是**绝对不许**做的（绕过闸、伪造数据、把认知逻辑塞进 backend）。

## 2. EmbodimentBackend 协议（必须实现的四个方法）

| 方法 | 真机要做什么 | 常见坑 |
|---|---|---|
| `capabilities() -> EmbodimentCapabilities` | 如实声明：支持哪些 `ActionKind`、有没有手臂、最大速度 | **不许乐观声明**。做不到的动作不要写进白名单 |
| `observe() -> Observation` | 从传感器 SDK 取位姿/电量/障碍，组装成观测 | 取不到就进 `missing`，**不许填默认值冒充** |
| `apply(action) -> ActionResult` | 过闸 → 下发给运动控制器 → 等结果 → 返回结构化结果 | 必须返回**分类的失败原因**，不能只返回 `False` |
| `estop(active: bool)` | 急停：**同时**置闸门 + 执行器 | 只置闸门 = 拦不住已经在动的电机（旧系统踩过）|

### 状态 → 动作的映射（以 Go2 这类四足为例）

| `ActionKind` | 可能的实现 | 备注 |
|---|---|---|
| `move(x, y)` | `sport_mode` 位置/速度指令（或路径点走） | 需要自己闭环到位姿判据，别假设"发出去就到了" |
| `turn(yaw)` | 转向控制 | 注意航向的正负约定 |
| `stop` | 站立/阻尼 | **永远要实现**（安全动作）|
| `wait(duration)` | 保持姿态 | |
| `inspect` | 读取当前区域/传感器快照 | |
| `grab` / `release` | 有机械臂才有；没手臂就**不要**写进 capabilities | 现在的仿真身体就是 `has_arm=False` |

## 3. 必须复用的东西（不许重新发明）

| 复用 | 为什么 |
|---|---|
| **同一个 `ActionGate`**（`argos/agent/gate.py`）| 安全判决只该有一处。真机可以**加严**（更小边界/更低速度），**不许放宽或绕过** |
| **缺数据 fail-closed 语义** | 真机上"定位丢失还继续走"比仿真危险得多 |
| `Watchdog` 的跳闸语义（跳闸→安全停止→不自动恢复）| 但真机应把看门狗做成**独立进程/硬件**，别和主循环同生共死 |
| `ActionResult` / `FailReason` 的结构 | 上层（反思、记忆、benchmark）全靠它分类 |
| `WorldState` 作为真相源、上层只拿 `WorldView` | 否则"谁都能改世界"的旧问题会复现 |

## 4. 接入步骤（未来照做）

1. 在 `argos/backends/go2/` 实现 `Go2Backend`，**只依赖** `argos.agent.interfaces` 与厂商 SDK；
2. 在 `argos/run.py::BACKENDS` 注册一行：`"go2": build_go2_backend`；
3. 用**同一套测试**跑一遍：闸门行为、缺数据 fail-closed、急停链路、看门狗；
4. 先跑 `--backend go2` 的**只读模式**（只 `observe()`，不发动作），确认观测可信；
5. 再开动作，且**初始速度上限压到最低**。

⚠️ 第 3 步不是可选项：**真机 backend 必须能跑通 `tests/test_action_gate.py` 的等价断言**。

## 5. 真机上会更难的地方（提前知道）

| 问题 | 仿真里的样子 | 真机上会怎样 |
|---|---|---|
| 到位判据 | 坐标直接等于目标 | 有误差 → 需要容差 + 超时 |
| 定位 | 真值直读 | 漂移/跳变 → `localization_error` 会变成常态失败 |
| 超时 | 逻辑时钟可算 | 墙钟 + 网络抖动，`action_timeout` 需要按真机实测重设 |
| 急停 | 一个标志位 | 必须真的有硬件通路，且**要能验证**（按一下它真停） |
| 电量 | 线性消耗模型 | 非线性、会跳变、有虚电 |
| 失败归因 | 结构化原因 | 厂商 SDK 常常只给错误码 → 需要一层映射，映射不上就**如实报 `executor_failure`** |

## 6. 红线（再强调一次）

1. **不许伪造**：没有硬件时**不写**真机实现、不写假的 `real_sport`、不把 `--backend go2` 做成"能跑但不真"。
   `python -m argos.run --backend go2` 现在**明确报"尚未实现"并退出码 2** —— 这是**正确行为**，别去"修"它。
2. **不许绕过闸门**：任何"为了让真机动起来"而放宽/跳过 `ActionGate` 的改动，都算安全事故。
3. **不许在 backend 里做认知**：路线选择、反思、记忆都不属于 backend。
4. **不许把仿真结论当物理结论**：`文档/SIMULATION.md` §1 那张表要一直带着看。
5. 真机代码只允许出现在 `argos/backends/go2/`；**认知层永远不许 import 硬件 SDK**。
