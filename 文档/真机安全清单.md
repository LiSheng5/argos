# 真机安全清单（上狗前必读）

> 2026-08-29。Go2 是 **15kg、最大 3000W、最高 3.7m/s** 的机器（宇树官网支持页参数）。
> 这不是玩具，软件里"诚实拒绝"写得再漂亮，也挡不住物理世界的惯性。
>
> **一句话原则：软件急停是最后一道，永远不是第一道。**

---

## 0. 软件挡不住什么

| 场景 | 软件能做 | 挡不住的原因 |
|---|---|---|
| 命令非法 / 越界 / 低电量 | ✅ SafetyGate 拒绝 | — |
| 按了急停 | ✅ 闸门 + 执行器同时收速（`backend.estop()`） | — |
| **链路断了，狗在走** | ✅ `LinkWatchdog` 超时收速 | 前提是进程还活着 |
| **进程被杀 / 电脑蓝屏 / 断电** | ❌ | 没人发得了停 |
| **狗端死机 / 电机失控** | ❌ | 我们的指令根本没被接收 |
| **狗已经在物理上冲出去了** | ❌ | 惯性 + 15kg |

→ 所以下面第 1 节（物理与人）**不是可选项**。

---

## 1. 物理与人（第一道防线，无替代）

- [ ] **有人在场**，且这个人手能立刻够到物理急停
- [ ] **物理急停**：手持遥控器（EDU/X 标配）上的急停，或带屏遥控器的 Stop
      —— 这是唯一在所有情况下都有效的停止手段
- [ ] **空旷场地**：先 3m×3m，别一上来就跑 10m。地面平整、无台阶、无宠物小孩
- [ ] **拴绳 / 限位**：第一次跑建议拴，或至少有人挡在前进方向上
- [ ] **电池满电**：低电量时狗会自己趴下（官方：黄灯慢闪 = 10 分钟内自动爬下），
      走一半趴下很尴尬
- [ ] **环境**：工作温度 5–35℃，别在冰面/湿滑地面跑

| 项 | 在哪 | 测试 |

## 3. 真机到手必须补的（现在做不到，别带着洞上狗）

- [ ] **接 BMS 真实电量**
      已知坑：`SportModeState_` 里**没有电量字段**，`sportmode_pose_source()`
      故意不填 `battery_pct` → 安全闸按"电量未知"只放行 `move_to`，**巡逻（navigate）会一直被拒**。
      不补这个，狗只能"去某地"，不能"巡逻"。
- [ ] **按真实场地配 `BOUNDARIES`**
      现在 `safety.py` 里是 ±10m 的**示例值**，不是你家的尺寸。
- [ ] **验 `sportmodestate` 的字段与单位**
      `position` 是机体系相对起点的航位推算（**会漂移**），`imu_state.rpy[2]` 是弧度。
      这是整个闭环的位姿来源，单位搞反 = 转反方向。
- [ ] **上电顺序**：先 `StandUp()` 站稳，再发速度；结束时 `StopMove()` + `StandDown()`
- [ ] **按实测重调增益**：`k_v` / `k_yaw` / `max_speed`。
      现在 `max_speed = 0.4 m/s`（官方示例 0.3，狗极限 3.7）—— **起步就该慢**
- [ ] **确认避障状态**：官方说明"绿灯常亮 = 开机完成，默认避障开启；蓝灯常亮 = 避障关闭"。
      跑之前确认是绿灯，别在避障关着的时候做自主行走。
- [ ] **看门狗超时值**：现在 1.0s。真机上按实际链路抖动调，别设太短导致误跳闸。

## 4. 操作纪律

- [ ] 第一次上电：**不跑闭环**，先用官方 `go2_sport_client.py` 手动发 `Move(0.3,0,0)` 走 1 米，
      确认方向、速度、停止都符合预期
- [ ] 第二次：用我们的 `RealSportEntity` 走 1 米（目标设在正前方，别带转向）
- [ ] 第三次才试转向，第四次才试多点巡逻
- [ ] **每步都留日志**：`store/robot_memory.json` 会记下每次成功/失败，
      出事后能复盘"它当时到底想干什么"
- [ ] 保修条款（官方）：**私自改造/开壳失效**；"开发者模式自建程序导致损坏"不保修。
      心里有数再上。

## 5. 出事之后

1. 物理急停（遥控器）
2. 别急着重启 —— 先看 `/api/memory` 里最后几条记了什么
3. 复现前先降到更保守的参数（`max_speed` 减半、`timeout` 缩短）
4. 把这个场景补成一个测试用例，钉住它
