## "要上真机还差什么"调研（2026-08-29）

来源：宇树官网支持页 support.unitree.com/home/zh/developer（2026，已核对）+ 随包 SDK 源码。

**硬门槛：Go2 分型号，只有部分支持二次开发**
| 型号 | AIR | PRO | X | EDU |
|---|---|---|---|---|
| 二次开发 | 无 | 无 | 基础支持 | 支持 |

AIR / PRO 官方层面**不开放** DDS 二次开发 → 整个真机路线走不通（除非绕过，不合规不建议）。

**关键洞察（能省几周）**
- `SportClient.Move(vx, vy, vyaw)` 已由狗自身小脑实现全向移动+转向；
  官方 `example/go2/high_level/go2_sport_client.py` 里就有 `Move(0,0,0.5)` 原地转。
  → 真机上**转弯不用自己调步态**，当前在 DDS 低层手调 trot 是"造轮子"路线。
- 全系自带 4D LiDAR-L2 + 探物避障（**开机默认开启**）→ 避障不用从零造。
- PRO/X/EDU 自带语音功能 → ASR/TTS 可能不必自研。
- 充电桩回充：仅 X / EDU 支持（和现有"回充电桩"日常对得上）。
- 足端力传感器、深度相机：仅 EDU 有。D1 舵机机械臂：选配 → 不装，grab 永远是假的。
- 位姿/SLAM：官方有 L2 SLAM 开源，雷达可选 MID-360 / 禾赛 XT16 做导航。

**待办（已并入 架构.md §9.1）**：装环境复验 → 定控制路线（高层 vs 低层）→ 真机安全
（物理急停/真实电量/场地边界/断连看门狗）→ 位姿闭环 → 避障 → 手臂 → 易用。

### 关键结论：高层 SportClient 在仿真里验证不了
- `UnitreeSdk2Bridge` **只订阅 `rt/lowcmd`**（低层电机指令），只发布 lowstate / sportmodestate 等状态。
- `SportClient.Move()` 走的是 **RPC 请求-响应**（`_Call(SPORT_API_ID_MOVE, ...)`），
  需要狗端有响应服务；unitree_mujoco 里**没有**这个服务端。
→ 没真机的情况下，高层接口只能"写好等验"，仿真闭环仍须走低层 DDS。
→ 落地建议：大脑层（编译/落账/安全闸/记忆/服务）用低层 DDS 在仿真里跑通并验证；
  执行器层按高层 SportClient 设计 `RealSportEntity` 接口，等真机到手只换执行器。
