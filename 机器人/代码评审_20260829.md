## 1. P0 —— 上真机前必须修

### P0-1 急停到不了执行器（安全）
`/api/estop` → `gate.set_estop()`，**仅此而已**。`RobotExecutor.estop()` 协议里定义了，
但全代码库没有任何一处调用它；`DdsEntity.move_to` 里那个 `self._estop` 也永远没人置位。

实跑验证：
```
gate.estop = True | executor.estop() 被调用过 = False
```
后果：急停只是"不再接新单"，**正在跑的那一段 trot 会跑完**（DdsEntity 单段最长 15s）。
真机上这是"按了急停狗还往前冲"。

### P0-2 tick 循环同步阻塞 asyncio（安全 + 可用性）
`server._tick_loop` 里直接 `brain.tick()`，而 tick 内部会一路同步调用到
`DdsEntity.move_to`（单目标最长 `WALK_TIMEOUT=15s`，`navigate` 4 个点可到 45s+）。
这段时间 event loop 是死的 —— **/api/command 和 /api/estop 完全无响应**。
与 P0-1 叠加 = 真机急停事实上失效。

### P0-3 无版本控制 + 无依赖清单
8-28 之后所有产出（brain/dds 调参/架构文档）都在裸目录上。DDS 步态参数是**实测调出来的**，
丢一次就得重调。建议：`git init` + 提交当前状态 + 补 `requirements.txt`。

## 2. P1 —— 会在真机上暴露的设计缺陷

### P1-1 navigate 的步骤粒度是错的
架构说"每 tick 恰一步"，但巡逻 4 个地点**在一次 tick 内全部跑完**：
```
一次 tick 的调用序列: [navigate(4), move_to(0,0), move_to(0,0), move_to(2,0), move_to(4,4)]
```
stub 里是瞬移所以看不出来，真机上一帧 = 走完 4 个房间。`navigate` 应拆成 N 步进 `steps` 队列。

### P1-2 默认地点表和 DDS v1 完全不兼容
`DEFAULT_PLACES` 桌边 `(2,0)`、门口 `(4,4)`，而 DDS 只沿 **-x** 走（`WALK_DIR=-1`）。
`move_to` 的第一个判据就是 `(x - 当前x) * WALK_DIR <= 0 → False`：

| 指令（--executor dds） | 结果 |
|---|---|
| 去桌边 (2,0) | `(2-0)*(-1) = -2 ≤ 0` → 失败 |
| 去门口 (4,4) | `\|y差\|=4 > 0.6` → 失败 |
| 回充电桩 (0,0)（已在原点） | `0*(-1)=0 ≤ 0` → 失败 |

**即 `python -m robot.server --executor dds` 开箱即 100% 走不动。**
`test_dds_walk` 是靠自己传 `places={"桌边": (-2.0, 0.0)}` 绕开的 —— 所以测试绿 ≠ 默认配置能跑。

### P1-3 test_dds_walk 大概率是 flaky 的（静态推演，未能实跑）
第二段断言"去门口 → 不会转弯 → 执行层诚实失败"，实际走的是**两条别的路径**：

1. `places` 里没有"门口"→ `compile_command` 返回 None → 根本没落账，走的是"听不懂"路径，
   不是"执行失败"路径 —— **测试意图与实现不符，v1 的"不会转弯就诚实失败"其实没被覆盖**；
2. 于是 `tick()` 转去跑自发日常，靠**随机**撞失败：
   - navigate（权重 3/6）→ `move_to(0,0)` 方向为负 → 失败 ✅
   - 去桌边（权重 2/6）→ 狗已经在 -2 附近，`dist ≤ ARRIVE_TOL(0.25)` **直接返回 True** → completed ❌
   - rest（权重 1/6）→ completed ❌

**通过概率约 50%。** 建议改成一个明确会转弯的目标点（如 `y` 偏移 > 0.6 的自定义地点），
把"不会转弯"变成确定性断言。

> 置信度说明：这一条是静态推演（本机无 mujoco 装不了），逻辑链已逐行核过，但请装完环境后实跑确认。

### P1-4 纵深防御有缝隙：waypoints 内嵌禁触字段不拦
```
顶层 file 字段:      (False, '参数涉及不安全的字段')   ← 拦住了
waypoints 内嵌 file: (True, '')                      ← 漏了
```
`safety.check` 的禁触扫描只扫 `params.values()` 顶层；`waypoints` 是 list，里面的
dict 不扫。虽然最终只取 x/y/yaw（实际危害有限），但"禁触字段"这条铁律应当是递归的。

### P1-5 记忆卡文件类型不设防
`store/robot_memory.json` 一旦被写成非数组（手改坏、写盘中断）：
```
AttributeError: 'dict' object has no attribute 'append'
```
服务直接起不来，且没有降级路径。`_load_memory` 应校验 `isinstance(list)`，坏了就备份+重建。

### P1-6 电量门控是 fail-open 的
```python
batt = float(state.get("battery_pct", 100.0))
```
执行器没上报电量时**按满电放行**。真机应该反过来：缺字段 = 未知 = 拒绝（或按 0 处理）。
同理 `_choose_routine` 里也是 `get("battery_pct", 100.0)`。

## 4. P3 —— 小毛病

1. `_near("充电桩")` 硬编码地点名；自定义 `places` 里没有"充电桩"时，低电量回桩会空转刷记忆。
2. `remember()` 每记一条就全量重写 JSON（上限 100 条），高频写放大。
3. `test_robot_safety.py` 里 `assert not ok and "ji" in reason or ...` 有遗留拼音串，
   且 `and/or` 优先级写法冗余（实际等价于 `not ok and ("ji" in reason or "急停" in reason)`）。
4. `tests/__pycache__` 里还留着 `4_robot` 时代的旧缓存（skip 提示里冒出
   `4_robot\tests\test_sim_smoke.py`）。

## 5. 做得对的地方（别改坏了）

- **落账口唯一 + 安全闸不可绕过**：接单（`book`）和执行（`backend.apply`）两条路径都过闸，
  白名单 / 禁触字段 / 急停 / 电量 / 边界五道检查一个不少。这是整个项目最值钱的部分。
- **诚实拒绝贯穿到底**：听不懂、急停、越界、失败冷却都如实回话，不空头承诺；
  自发日常完成不写记忆卡（源头断噪音）；`DdsEntity` 不会转弯就 `return False` 而不是硬走 ——
  这个态度对真机是对的。
- **记忆降级不删除**：超限只置 `archived`，卡上永不物理删除；反思只复述不编造。证据链红线守住了。
- **三层执行器接口一致**（stub / mujoco / dds），切换只改一处注入。
- **本机服务的细节到位**：只绑 127.0.0.1、Origin 校验、Windows GBK 请求体兜底、急停默认置位。
- **SKILL.md 与实际一致**：失败冷却写"约 15 秒"= 5 tick × 3s，对得上。
